# Backtesting and Evaluation

Backtesting evaluates a forecasting approach across historical forecast origins using the same target, grain, horizon, and feature availability rules used for production scoring.

## Rolling-Origin Contracts

Backtest runs are defined by `vertex/config/backtest_contract.yaml`. A contract declares:

- the forecast contract to evaluate
- the model config to train and score
- the historical forecast origins
- the required horizons
- the training lookback window
- segment columns for metric breakdowns
- baseline models
- metric policy and promotion gates

The contract is validated before a runner trains or scores anything. Horizons must be a subset of the forecast contract horizons, origins must be explicit or generated by an origin policy, and baseline names must come from the supported baseline list.

The model configuration must declare `inputs.prediction_horizons`, and those horizons must exactly match the backtest contract. The default contract uses `favorita_store_h7_xgboost`, a direct horizon-7 model trained on `sales_store_n7d_same_dow` (sales exactly seven calendar days after the forecast origin). It does not reuse the one-day model or treat cumulative next-seven-day demand as a point forecast.

Validate a contract and inspect its expanded origin plan with:

```bash
make vertex-backtest-plan
```

## Origins and Cutoffs

Each origin represents the information set available at that point in time. For a daily next-period demand target, training data must stop before the origin if the label depends on future demand. Scoring rows use features available at the origin and produce horizon-specific forecasts.

## Baselines

The first supported baseline names are:

- `zero_demand`
- `last_observation`
- `seasonal_naive_7d`
- `same_period_last_year`
- `moving_average`
- `croston_sba_tsb`

Local deterministic scoring is implemented for `zero_demand`, `last_observation`, `seasonal_naive_7d`, and `moving_average`. Scoring uses actuals available through each origin and evaluates against the actual at `origin + horizon`. Baselines that lack sufficient history emit a null prediction so prediction completeness remains auditable.

Run baseline scoring against a local history extract containing the configured entity, date, actual, and segment columns:

```bash
make vertex-backtest VERTEX_BACKTEST_INPUT=path/to/history.csv
```

The command prints a stable backtest run ID and aggregate/segment metric records. BigQuery persistence is deferred until baseline and model-scoring records share the same contract.

## Metric Policy

Backtest selection should use comparable keys:

```text
target x grain x horizon x segment_key_json x metric_policy
```

R2 is not a primary model-selection metric for demand forecasting because demand series are often intermittent, sparse, and scale-dependent. Prefer WAPE, MAE, scaled errors, bias, completeness, and quantile calibration metrics.

The first scoring slice calculates WAPE, MAE, mean signed error (`bias`), and prediction completeness. WAPE is null when the sum of absolute actual demand is zero; completeness still reports normally.
